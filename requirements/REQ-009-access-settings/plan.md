# 权限与系统设置

## 业务背景与范围

系统需要提供统一登录入口，确保投研工作台在访问权限控制下使用。本期使用模拟登录账号，覆盖登录、退出和登录后进入工作台的基础流程，并与部门、角色、项目和模块级权限隔离能力衔接。

本期不包含“记住我”、忘记密码和验证码；不接入真实身份认证服务。

## 用户故事与场景

- 作为系统用户，我希望输入账号和密码登录，以便进入投研工作台。
- 作为登录用户，我希望看到明确的登录加载和失败反馈，以便知道当前认证状态。
- 作为已登录用户，我希望退出登录，以便结束当前访问会话。
- 作为系统管理员，我希望按部门、角色、项目和模块控制访问范围，以便隔离投研数据。

## 验收标准

### AC-1: 登录页面

页面展示账号输入框、密码输入框和登录按钮；账号或密码为空时，阻止提交并展示字段提示。

### AC-2: 模拟登录

输入有效模拟账号后提交，页面展示 Loading 状态；认证成功后建立模拟登录状态并跳转投研工作台。

### AC-3: 登录失败

输入无效账号或密码时，页面展示明确的登录失败提示，保留用户输入的账号并允许重新提交。

### AC-4: 退出登录

已登录用户执行退出操作后，清除模拟登录状态并返回登录页面；未登录用户不得访问受保护的工作台页面。

### AC-5: 访问权限

系统按部门、角色、项目和模块返回模拟权限范围；用户只能查看或操作授权范围内的内容。

### AC-6: 基础三态

登录请求处于处理中、返回失败或无可用权限时，页面分别展示 Loading、Error 或 Empty 状态，并提供合理的下一步操作。

## 页面结构与组件骨架

- 登录页面
	- 产品标识与页面标题
	- 账号输入框
	- 密码输入框
	- 登录按钮
	- 登录 Loading 状态
	- 登录失败提示
- 受保护的投研工作台
	- 当前用户信息
	- 退出登录入口
	- 按权限显示的业务模块入口
- 系统设置页面
	- 部门与角色权限
	- 项目与模块授权
	- 信息源与采集规则配置
	- 研判规则配置
	- 尽调检查要点配置
	- 反馈样本管理

## UI/UX 三态规格

- Loading：登录按钮进入稳定的提交中状态，避免重复提交。
- Error：展示登录失败原因，账号输入保持可编辑。
- Empty：用户无任何授权模块时展示无权限状态，不渲染空白工作台。

## 主 UI 风格

沿用项目确认的“数据密集型投研工作台”。登录页面作为入口保持克制、清晰，并与登录后的工作台视觉语言一致。

## 技术契约与数据模型

- `LoginCredentials`：`username`、`password`。
- `AuthUser`：`id`、`name`、`department`、`roles`、`permissions`。
- `AuthState`：`user`、`isAuthenticated`、`isLoading`、`error`。
- `login(credentials)`、`logout()`、`getCurrentUser()` 均通过 `src/services/` 返回 `Promise`。
- Mock service 使用 300-800ms 的 `setTimeout` 模拟认证延迟，并提供成功、失败和无权限场景。
- UI 不直接引用 `src/mocks/`；Zustand store 管理认证状态和受保护路由所需的用户权限。
