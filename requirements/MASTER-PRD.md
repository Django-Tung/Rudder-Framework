# 全局主 PRD

> 本文件是项目级需求主记录。它记录跨 REQ 共享的业务规则、术语、已确认的 UI 主风格和待批准的需求拆分。
> 不属于任何阶段，不设置 `status` / `phase`。REQ 的状态与索引由各 REQ 的 `README.md` 和自动索引维护。

## 1. UI 主风格

- 预设：`P1` · 清爽后台
- 来源：用户未指定，采用默认预设
- 令牌集：`src/index.css` 的 `@theme`（随预设同步，取值见 `.rudder/design/visual.md` §4）
- 例外：无
- 确认日期：2026-10-02

**取值只允许**：`P1`（清爽后台）/ `P2`（深色数据台）/ `P3`（温暖内容型）/ `BRAND`（客户品牌色派生）。
**不接受自由文本描述**——用户无法描述视觉，预设包图示见 [`docs/styles/`](../docs/styles/)。

> 首次执行 `/rudder-import` 或 `/rudder-plan` 时，向用户展示三套预设图示并询问：
> 「① 选 P1 / P2 / P3 哪一个？② 或者直接说『你决定』」。
> 选 ② 即采用默认预设 `P1` 并记录「用户未指定」——**流程不得因此卡住**。
> 后续入口必须展示当前预设并询问是否沿用或调整。

## 2. 业务场景与假数据基线

> 假数据是原型质量里**性价比最高**的一项投入：成本几乎为零，但对客户观感影响最大。
> AI 默认生成的 `张三` / `测试数据1` / `item-001` 会让客户第一眼就出戏——
> 注意力从「你的方案怎么样」转移到「这东西是不是真的」，而后者对原型评估没有价值。
>
> **由 `/rudder-import` 或首次 `/rudder-plan` 向用户确认后填写**（可答「你决定」，
> 此时由 AI 按需求领域生成合理默认值并记录来源）。详见 `.rudder/design/assets.md`。

- 业务领域：待确认
- 典型机构与角色：待确认
- 真实感数值区间：待确认（如：订单金额 5 千 ~ 80 万；交期 3 ~ 45 天）
- 状态流转真实形态：待确认（如：草稿 → 待审核 → 已通过 → 已终止；禁用 `active` / `inactive`）
- 列表数据量下限：12 条（须填满首屏并有滚动余量）
- 占位内容黑名单（**始终生效，无需确认**）：
  `Lorem ipsum` · `test` / `Test` · `示例` · `样例` · `xxx` · `公司A` · `用户1` ·
  `item-001` · 连续整数日期（如 `2024-01-01`、`2024-02-01` 连号）

> 新项目在首次规划时填写；**老项目在首次发生变更（`/rudder-change`）时补填**，
> 避免历史 REQ 被新规则追溯判死。
