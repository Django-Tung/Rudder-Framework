# 语义分析: 供应商管理模块需求说明（IMP-20260922-001）

> 原文为 `imported.md`（由 `scripts/import-docx.js` 从 `source/sample.docx` 转换）。

## Business Goal

统一维护供应商主数据，替代当前由多个 Excel 分散管理的现状。

## Actors

| 角色 | 职责 |
|---|---|
| 供应商数据维护人员 | 查看与维护供应商主数据 |

> ⚠️ 原文未点名角色，上表为依据「统一维护供应商主数据」的**推定**，已登记为澄清问题。

## Functional Requirements

- [FR-1] 供应商列表展示：供应商名称（原文：§二 2.1）
- [FR-2] 供应商列表展示：统一社会信用代码（原文：§二 2.1）
- [FR-3] 供应商列表展示：合作状态（原文：§二 2.1）
- [FR-4] 接口失败时展示错误提示并提供重试入口（原文：§二 2.2）

## Business Rules

- [BR-1] 所有金额字段单位为人民币元（原文：§一）
- [BR-2] 所有时间字段统一使用 `YYYY-MM-DD` 格式（原文：§一）

> BR-1 / BR-2 声明的是全模块通用的单位与格式约定，符合「全局规则」特征，
> 建议归入 `requirements/MASTER-PRD.md` 的「全局业务规则」，**不**拆为独立 REQ。

## Non-functional Requirements

- [NFR-1] 列表加载期间展示骨架屏（原文：§三）
- [NFR-2] 无数据时展示空状态提示（原文：§三）

> 这两条是 UI 状态要求而非独立功能点，随供应商列表 REQ 一并实现，不单独拆 REQ。

## Dependencies

| 功能 / 模块 | 依赖对象 | 说明 |
|---|---|---|
| 供应商列表 | 供应商查询接口 | 原文未给出接口定义，仅有「接口失败」的表述 |
| 供应商列表 | 错误提示 / 重试入口 | 与 §二 2.2 同一交互 |

> 本次拆分的两个 REQ 之间**无**跨 REQ 依赖：`dependencies` 均为空列表。

## Constraints

- 输入格式仅支持 `.docx` / `.md` / `.txt`（PDF 与 xlsx 为 Non-Goal）。
- 原文未提及技术栈、性能指标与合规要求。

## Ambiguities

- 使用角色未点名（谁能看、谁能改）。
- 「合作状态」的取值集合未定义。
- 「统一社会信用代码」是展示原文还是脱敏展示？
- 列表是否需要分页 / 排序 / 筛选？
- 错误提示与重试入口是独立的 §二 2.2 功能点，还是列表的一部分？
- 附录（§附录）没有业务含义，仅为还原 Word 层级，是否可忽略？

## Risks

- 原文缺少接口契约，实现阶段需自行定义 mock schema，存在返工风险。
- 「合作状态」取值未定，会导致 mocks 与 UI 标签需要二次修改。
