# IMP 管道 — 解析与语义分块的解耦

> 本文件回答「**谁负责把文档变成文本、谁负责理解它**」。
> 输入类型见 [`sources.md`](sources.md)，产物约定见 [`normalization.md`](normalization.md)。

## 1. 职责切分（关键）

| 环节 | 责任人 | 手段 | 确定性 |
|---|---|---|---|
| **文档解析** | **确定性脚本** | `node scripts/import-docx.js <file>`（`mammoth`） | ✅ 可重复、可 diff |
| **语义分块** | **AI** | 读取归一化 Markdown，识别全局规则与独立功能点 | ❌ 需判断力 |

**这条分界是硬的**：

- 解析**禁止**由 AI 完成。Agent **不得**直接读取二进制 `.docx`，**不得**自行解析其 XML，
  也不得用"我大概能猜出内容"绕过脚本。二进制格式的解析属于确定性工作，交给脚本才有可重复性。
- 分块**禁止**由脚本完成。"这段是全局规则还是某个功能点的描述"是语义判断，写不成正则。

## 2. 解析行为约定

`scripts/import-docx.js` 用 `mammoth` 把 `.docx` 转为 Markdown：

- **保留**：标题层级、列表层级——这些是后续分块的主要结构信号。
- **忽略**：图片、复杂排版（表格样式、文本框、页眉页脚等）。
- 输出落在 IMP 目录的 `imported.md`（见 [`normalization.md`](normalization.md)）。

> 忽略图片是**有意的**：原型需求文档的结构信息主要靠标题与列表承载，
> 图片无法稳定转成可 diff 的文本，强行提取会引入不可复现的输出。

## 3. `mammoth` 转义说明

`mammoth` 输出的 Markdown 含**合法的反斜杠转义**，例如：

- `YYYY\-MM\-DD`（原文档中的连字符，避免被解析为列表）
- `2\.1`（原文档中的编号点，避免被解析为有序列表）

这些转义**渲染正确**，无需还原。AI 分块时：

- **必须**忽略转义符号，按**渲染后的语义**理解内容；
- **禁止**尝试还原或改写这些转义（改写会破坏与 `imported.md` 的可追溯性，
  且下一次重新导入时又会出现）。

## 4. 禁止的捷径

以下行为一律视为违规：

| 违规行为 | 为什么不行 |
|---|---|
| 直接读 `.docx` 二进制 | Agent 不在脚本的确定性保护范围内，结果不可复现 |
| 自行解析 `word/document.xml` | 同上，且 mammoth 已处理了 XML 的复杂度（样式映射、编号等） |
| 跳过 `imported.md` 直接凭记忆分块 | 分块结论与 `analysis.md` 会失去可追溯的输入 |
| 为了让分块"更好做"而手改 `imported.md` | 破坏与 `source/` 原件的对应关系 |
