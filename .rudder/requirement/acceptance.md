# 验收标准（AC）编号规范

> 本文件回答「**`plan.md` 里的 AC 该怎么编号**」。REQ 目录结构见 [`structure.md`](structure.md)。

## 1. 编号格式

验收标准**必须**以 `AC-N` 形式编号，`N` 从 1 开始，连续递增：

- ✅ `AC-1`、`AC-2`、`AC-3`
- ❌ `AC1`、`AC-01`、`AC_1`、`场景 1`

编号是**机器可读的键**，不是展示文案。

## 2. 声明格式

`plan.md` 中每一条 AC 用以下任一格式声明（`scripts/check-req.js` 的 I1 断言兼容两者）：

```markdown
- **AC-1: 正常登录**
  - **Given** 用户处于登录页且网络正常
  - **When** 输入正确的邮箱和密码并点击登录
  - **Then** 按钮显示 Loading 状态，800ms 后跳转至首页
```

或旧式标题：

```markdown
### AC-1: 正常登录
```

推荐前者——它与模板 [`.rudder/templates/plan.md`](../templates/plan.md) 一致。

## 3. 内容要求

- **必须**用 Given-When-Then 格式。
- **必须**用**简体中文**书写（技术术语可保留英文）。
- 一条 AC 描述一个**可独立验证**的行为，不要把多个行为塞进一条。
- **异常流与边界情况也必须各自编号**（如 `AC-4: 服务器错误`），
  否则 Implement 完成检查没有核对基准。

## 4. 可判定性要求（STRICT）

> 本节回答「**什么样的 AC 算合格**」。编号规范是机器识别的前提，**可判定性是人工核对的前提**——
> 缺了它，`implement.md` 的 AC 实现核对表无从核对。

**每条 AC 的 `Then` 必须包含「可观察的具体行为」**——即界面上**出现的文字、元素、状态、数值**。
不得只写主观判断。

| 判定 | 例子 |
|---|---|
| ❌ 不可判定 | 「页面要美观易用」「错误状态要友好提示用户」「加载要快」「排版要清晰」 |
| ❌ 不可判定 | 「提示用户输入正确的邮箱」（"正确"由谁定义？） |
| ✅ 可判定 | 「接口返回 500 时，列表区域显示左侧红色边框的 Alert，文案为『加载供应商失败，请稍后重试』，右侧提供『重试』按钮，点击后重新请求」 |
| ✅ 可判定 | 「邮箱为空时提交，邮箱输入框下方显示红色文案『请输入邮箱』，且提交按钮为禁用态」 |

### 4.1 为什么强制

Rudder 已有两条机器断言：I1（AC 被任务覆盖）、I2（虚假完成）。但它们查的是**文档之间的引用完整性**，
不是**代码与需求的一致性**。因此完全可能出现：

> AC 写「空状态显示引导按钮」→ 任务打勾 → 代码画了个光秃秃的「暂无数据」→ 5 条 npm 命令全绿 → I1/I2 通过
> ——**但页面不满足 AC**。

`implement.md` 的 **AC 实现核对表**（AI 填实现位置，用户勾结论）是对账环节，
而**对账的前提是 AC 本身可判定**。写不出可观察行为的 AC，既让核对无从下手，
也说明**业务方自己也没想清楚要什么**——这正是 Plan 阶段应当继续澄清的信号。

### 4.2 检查时机

`/rudder-plan-confirm` 必须把可判定性作为**检查项**：

> 逐条检查 AC 的 `Then` 是否包含可观察的具体行为。
> 凡写不出具体可观察行为的 AC，**退回重写**，不得推进到 `APPROVED`。

---

## 5. 为什么编号是强制的

`scripts/check-req.js` 的 **I1（拆解完备）** 断言：**`plan.md` 的每条 AC 编号，在 `tasks.md` 中至少出现一次**。

- 每条任务拆解时**必须**标注对应的 AC 编号（如 `[T-03] ... （对应 AC-2）`）。
- 编号不规范（写成 `AC1` / `场景 1`）会让 I1 **形同虚设**——脚本找不到编号，断言永远通过。

因此编号规范不是风格偏好，而是**校验有效性的前提**。

## 6. 编号的生命周期

| 场景 | 编号处理 |
|---|---|
| 新增需求内容 | **追加**新编号（`AC-7`、`AC-8`…），**不得**重排已有编号 |
| 修改已有 AC 的内容 | **保留**原编号，在 Change Log 中记录变更 |
| 删除某条 AC | **保留编号空缺**，不要用后续编号填补 |

**编号一旦发布就不可复用**——实施检查与 `tasks.md` 的任务标注都引用了编号，
重排会让历史记录指向错误的条目。
