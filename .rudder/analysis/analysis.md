# `analysis.md` 粗拆分产物规格

> 本文件定义 IMP 在 `analyzed` 状态时产出的轻量分析结构。
> Import 只负责粗略读取和拆分候选功能点；详细设计统一由 `/rudder-plan REQ-XXX` 完成。

## 1. 定位

`analysis.md` 是对 `imported.md` 的人读摘要，与 `pending_maps` 同时产生：

- `analysis.md` 记录文档大意、候选功能点和明确的上下文；
- `pending_maps` 记录候选 REQ、优先级和明确依赖。

Import 不负责编写 PRD、AC、页面结构、UI 三态、数据模型、Service 契约或实施任务。

## 2. 结构：5 个小节

`analysis.md` 必须按以下顺序包含 5 个小节：

| # | 小节 | 内容 |
|---|---|---|
| 1 | `文档概览` | 文档主题、目标和范围的简短摘要 |
| 2 | `候选功能点` | 可能独立交付的功能点及原文位置 |
| 3 | `明确的共享规则与术语` | 文档明确写出的共享规则和术语，不补充新规则 |
| 4 | `明确的依赖` | 文档明确写出的功能或外部依赖 |
| 5 | `待 Plan 确认` | 不确定、缺失或需要详细设计阶段确认的内容 |

## 3. 写作约束

- 正文使用简体中文，标题使用上表中的固定中文名称。
- `候选功能点` 至少列出一个条目，并尽量标注原文位置。
- 只能记录文档明确表达的内容，不得在 Import 阶段补全业务逻辑或技术方案。
- 不确定内容放入 `待 Plan 确认`，由 `/rudder-plan` 在人工确认后形成正式 PRD。
- `明确的共享规则与术语` 只记录候选项，是否进入 `MASTER-PRD.md` 由人工确认。
- `明确的依赖` 只记录文档明确表达的依赖，不能根据猜测填写。

## 4. 最小示例

```markdown
# 粗拆分分析：供应商管理需求

## 文档概览

文档描述供应商信息的查看和维护范围。

## 候选功能点

- [REQ-CANDIDATE-1] 供应商列表（原文：第 2 节）
- [REQ-CANDIDATE-2] 供应商信息维护（原文：第 3 节）

## 明确的共享规则与术语

- 供应商：为平台提供商品或服务的合作方。

## 明确的依赖

- 供应商信息维护依赖供应商列表中的数据标识。

## 待 Plan 确认

- 列表是否需要分页、筛选和排序，进入 Plan 阶段确认。
```
