# 演示前检查清单

> `/rudder-commit` 完成后，由 AI **主动提示**你走一遍。
> **不阻断流程**——它是提醒，不是门禁（见设计决策 D12）。
>
> 场景：**会议室投屏**。目标客户面前不出戏。

---

## 1. 启动与画面

- [ ] `npm run dev` 启动无报错，浏览器打开 `http://localhost:5173`
- [ ] 浏览器窗口已最大化，或宽度 **≥ 1280px**（投屏画面被拉伸会明显掉档次）
- [ ] **浏览器标签页标题是项目名**，不是「Rudder Framework」
      → 见 `index.html` 的 `<title>`，首次规划时写入
- [ ] 页面没有滚动到一半的残缺布局

## 2. 走一遍演示动线

对照 `implement.md` 的「**演示动线**」逐条走，每条都点一遍：

- [ ] 开场页正常打开
- [ ] 每一步的跳转都生效
- [ ] 没有空白页
- [ ] 页面里搜不到 `undefined` / `NaN` / `null` / `[object Object]`
- [ ] 收尾画面正常

## 3. 假数据不出戏

> AI 默认生成的 `张三` / `测试数据1` / `item-001` 会让客户第一眼就出戏。

- [ ] 所有页面的 mock 数据**非空**（不是「暂无」状态）
- [ ] 抽查 **3 条**数据，符合 `MASTER-PRD.md` §2「业务场景与假数据基线」
- [ ] 没有 `Lorem ipsum` / `test` / `示例` / `xxx` / 连续整数日期
- [ ] 列表数据量够滚动（≥ 12 条）
- [ ] 金额、日期、数量看起来像真实业务

## 4. 断网演示（**这一条最重要，也最容易被跳过**）

> 会议室网络经常需要访客认证、有线口不通、临时 WiFi 不可用。
> 联网时测不出外链依赖——图也能加载，会**掩盖违规**。

- [ ] 关掉 WiFi / 拔掉网线，刷新页面
- [ ] **没有任何图片加载失败**（无裂图、无空白框）
- [ ] 字体、图标正常显示
- [ ] 所有交互仍然可用

## 5. 你自己要知道的事

- [ ] **加载等待 0.3~0.8 秒**：这是模拟网络延迟，用来展示加载态设计，真实接入后不会有
- [ ] **可能跳到「服务器开小差了」**：这是模拟服务端错误，用来展示异常处理设计
      → 演示前建议想好怎么跟客户解释这一句
- [ ] 数据全部是**模拟数据**，用于展示业务逻辑与流程

> AI **不会替你生成这段话术**（设计决策 D10）——你临场自己说就行。

## 6. 临时补救

演示当天出问题时的兜底：

| 症状 | 临时处理 |
|---|---|
| 某个交互没反应 | 按演示动线的「兜底」跳到下一个能展示的页面 |
| 数据不对但来不及改 | 直接讲业务规则，跳过这张页面 |
| 页面崩了 | 刷新一次；仍不行则切到能跑的页面继续讲，**不要现场排查** |
| 网络彻底不通 | 走第 4 条——本项目零外网依赖，断网应该完全不影响 |
